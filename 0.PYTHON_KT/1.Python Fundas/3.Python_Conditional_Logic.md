## 1. Checking Whether an Age Is Between 18 and 55

The first example checks whether a person's age falls inside a particular range.

```python
# Age is between 18 and 55

age = 63

if age >= 18 and age <= 55:
    print("Age is Between")
else:
    print("Age is not Between")
```

### Output

```text
Age is not Between
```

### How it works

The condition contains two comparisons:

```python
age >= 18
age <= 55
```

They are connected using `and`:

```python
age >= 18 and age <= 55
```

For the entire condition to be `True`, **both conditions must be true**.

For `age = 63`:

- `63 >= 18` → `True`
- `63 <= 55` → `False`
- `True and False` → `False`

Therefore, Python executes the `else` block.

### Python chained comparison

Python also allows the same condition to be written more naturally:

```python
if 18 <= age <= 55:
    print("Age is Between")
else:
    print("Age is not Between")
```

Both versions express the same idea.

## 2. Checking Whether a Student Passed All Subjects

Suppose a student has marks in three subjects and must score at least `35` in **every subject** to pass.

```python
# Check Student Pass or Failed

m1 = 89
m2 = 92
m3 = 52

if m1 >= 35 and m2 >= 35 and m3 >= 35:
    print("Pass")
else:
    print("Failed")
```

### Output

```text
Pass
```

All three comparisons must be `True` because they are joined using `and`.

| Subject | Mark | Condition | Result |
|---|---:|---|---|
| 1 | 89 | `89 >= 35` | `True` |
| 2 | 92 | `92 >= 35` | `True` |
| 3 | 52 | `52 >= 35` | `True` |

Therefore:

```text
True and True and True
```

produces:

```text
True
```

### Another example

```python
m1 = 89
m2 = 92
m3 = 30
```

Now:

```python
m3 >= 35
```

is `False`, so the student fails.

### Important lesson

Use `and` when **every requirement must be satisfied**.

## 3. Classifying a Number by Number of Digits

The next example introduces a longer `if-elif-else` chain.

The program classifies a non-negative integer as:

- single digit
- two digit
- three digit
- other

```python
# Check Num => Single Digit / Two Digit / 3 Digit / Other digit

n = int(input("Enter num : "))

if n >= 0 and n <= 9:
    print("Single Digit Num")
elif n >= 10 and n <= 99:
    print("Two Digit Num")
elif n >= 100 and n <= 999:
    print("Three Digit Num")
else:
    print("Other Digit Num")
```

### Example

```text
Enter num : 365
Three Digit Num
```

### Execution flow

Python tests the conditions **from top to bottom**.

For `365`:

```python
365 >= 0 and 365 <= 9
```

is false.

Then:

```python
365 >= 10 and 365 <= 99
```

is false.

Then:

```python
365 >= 100 and 365 <= 999
```

is true.

Python prints:

```text
Three Digit Num
```

and skips the remaining `else`.

### Cleaner Python syntax using chained comparisons

The instructor also demonstrates that:

```python
n >= 0 and n <= 9
```

can be written as:

```python
0 <= n <= 9
```

The complete program can therefore be written as:

```python
n = int(input("Enter num : "))

if 0 <= n <= 9:
    print("Single Digit Num")
elif 10 <= n <= 99:
    print("Two Digit Num")
elif 100 <= n <= 999:
    print("Three Digit Num")
else:
    print("Other Digit Num")
```

### Beginner note: negative numbers

The lecture conditions classify negative numbers as `"Other Digit Num"`.

Mathematically, `-7` contains one numerical digit, but it does **not** satisfy:

```python
0 <= n <= 9
```

This is expected based on the conditions used in this exercise.

## 4. Character Classification

The next program determines whether an entered character is:

- uppercase alphabet
- lowercase alphabet
- digit
- symbol

```python
# Character => Upper case / Lower Case / Digit / Symbol

ch = input("Enter Character : ")

if ch >= 'A' and ch <= 'Z':
    print("Upper case alphabet")
elif ch >= 'a' and ch <= 'z':
    print("Lower Case alphabet")
elif ch >= '0' and ch <= '9':
    print("Digit")
else:
    print("Symbol")
```

### Example

```text
Enter Character : R
Upper case alphabet
```

### Why can strings be compared?

Characters have an ordering based on their Unicode code points.

Therefore, a test such as:

```python
'A' <= ch <= 'Z'
```

can determine whether a character falls in the uppercase English-letter range.

Similarly:

```python
'a' <= ch <= 'z'
```

checks lowercase English letters, while:

```python
'0' <= ch <= '9'
```

checks digit characters.

The program can therefore be written more compactly as:

```python
ch = input("Enter Character : ")

if 'A' <= ch <= 'Z':
    print("Upper case alphabet")
elif 'a' <= ch <= 'z':
    print("Lower Case alphabet")
elif '0' <= ch <= '9':
    print("Digit")
else:
    print("Symbol")
```

### Important beginner clarification

`input()` returns a **string**.

If the user enters:

```text
7
```

then `ch` contains:

```python
"7"
```

not the integer:

```python
7
```

That is why the program compares against `'0'` and `'9'`, not `0` and `9`.

### Assumption in this exercise

This example is intended for **one character**. If the user enters multiple characters, lexical string comparison can produce results that do not match the intended classification.

A safer version could first check:

```python
if len(ch) != 1:
    print("Please enter exactly one character")
```

a = 10

# 6. Finding the Largest of Three Numbers

To find the largest among three values, more than one comparison may be required.

```python
a = 10
b = 20
c = 15

if a > b and a > c:
    print("a is big")
elif b > c:
    print("b is big")
else:
    print("c is big")
```

### Why does the second condition only check `b > c`?

The first condition already established whether `a` is larger than both other values.

If that condition is false, the remaining decision is made between `b` and `c` in the lecture's simplified distinct-value example.

For:

```python
a = 10
b = 20
c = 15
```

the first condition is false:

```python
10 > 20 and 10 > 15
```

Then:

```python
20 > 15
```

is true.

Output:

```text
b is big
```

### Equality note

As with the two-number example, equal maximum values require extra handling if the program must report ties.

# 7. Finding the Largest of Four Numbers

The lecture extends the same idea to four numbers.

```python
a, b, c, d = 12, 45, 34, 25

if a > b and a > c and a > d:
    print("a is big")
elif b > c and b > d:
    print("b is big")
elif c > d:
    print("c is big")
else:
    print("d is big")
```

### Output

```text
b is big
```

### Understanding multiple assignment

This line:

```python
a, b, c, d = 12, 45, 34, 25
```

assigns four values at once:

```text
a = 12
b = 45
c = 34
d = 25
```

### Decision process

First:

```python
a > b and a > c and a > d
```

asks whether `a` beats **all three** other numbers.

If not, the program checks:

```python
b > c and b > d
```

Then:

```python
c > d
```

If none of those conditions is true, `d` is selected.

### Python built-in alternative

Later, when built-in functions are appropriate, Python can simply do:

```python
largest = max(a, b, c, d)
print(largest)
```

However, the purpose of the lecture example is to practice conditional logic, so the `if-elif-else` solution is important.

# 8. Nested `if`: Pass First, Then Calculate Grade

The next example combines:

1. pass/fail validation
2. average calculation
3. grade assignment

The grade should only be calculated when the student passes **every subject**.

```python
# Check Student Pass (then display grade) or Failed

m1 = 67
m2 = 56
m3 = 72

if m1 >= 35 and m2 >= 35 and m3 >= 35:
    avg = (m1 + m2 + m3) / 3

    if avg >= 75:
        print("Grade-A")
    elif avg >= 60:
        print("Grade-B")
    else:
        print("Grade-C")
else:
    print("Failed")
```

This is a **nested `if`** because another conditional statement exists inside the first `if` block.

### Step 1 — Check individual marks

```python
if m1 >= 35 and m2 >= 35 and m3 >= 35:
```

The student must pass all three subjects.

### Step 2 — Calculate the average

Only after passing:

```python
avg = (m1 + m2 + m3) / 3
```

For the lecture values:

```text
67 + 56 + 72 = 195
195 / 3 = 65
```

Therefore:

```text
avg = 65.0
```

### Step 3 — Determine the grade

```python
if avg >= 75:
    print("Grade-A")
elif avg >= 60:
    print("Grade-B")
else:
    print("Grade-C")
```

Since:

```text
65 >= 75 → False
65 >= 60 → True
```

the result is:

```text
Grade-B
```

### Why nesting is useful

The grade calculation should happen **only if the student has passed every subject**.

This reflects an important programming pattern:

```text
First validate eligibility
        ↓
If eligible
        ↓
Perform additional processing
```

# 9. Month Number → Number of Days

The next nested-condition example accepts a month number and displays the number of days.

```python
# Read Month Num => Display Num of Days

m = int(input("Enter month num : "))

if m >= 1 and m <= 12:
    if m == 2:
        print("28/29 days")
    elif m == 4 or m == 6 or m == 9 or m == 11:
        print("30 days")
    else:
        print("31 days")
else:
    print("Invalid Month")
```

### Outer condition — validate the month

```python
if m >= 1 and m <= 12:
```

Only numbers from `1` through `12` represent valid months.

A Python chained comparison can also be used:

```python
if 1 <= m <= 12:
```

### February

```python
if m == 2:
    print("28/29 days")
```

February has 28 days normally and 29 during a leap year.

This particular program does not ask for a year, so it simply displays:

```text
28/29 days
```

### 30-day months

```python
elif m == 4 or m == 6 or m == 9 or m == 11:
    print("30 days")
```

These correspond to:

- April (`4`)
- June (`6`)
- September (`9`)
- November (`11`)

Here `or` is appropriate because **any one** of these conditions is sufficient.

### Remaining valid months

```python
else:
    print("31 days")
```

If the month is valid, but it is not February and not one of the four 30-day months, it must be a 31-day month.

### Invalid input

For:

```text
Enter month num : 15
```

the outer condition fails and the program prints:

```text
Invalid Month
```

### Cleaner membership syntax

After learning collections, this condition:

```python
m == 4 or m == 6 or m == 9 or m == 11
```

can be expressed as:

```python
m in (4, 6, 9, 11)
```

But the lecture version is valuable because it directly practices the `or` operator.

# 10. Multi-Level Nested `if`: Eligibility Example

The lecture then demonstrates deeper nesting using an eligibility scenario.

The screenshot's teaching example checks three conditions in sequence:

1. gender must be `M`
2. age must be between 18 and 55
3. weight must be between 50 and 90

```python
# Check Person can donate blood or not
# 1. Only Males, 2. Age => 18-55, 3. Weight => 50-90

gender = 'F'
age = 23
weight = 55

if gender == 'M':
    if age >= 18 and age <= 55:
        if weight >= 50 and weight <= 90:
            print("Can donate blood")
        else:
            print("Weight issue")
    else:
        print("Error : Age issue")
else:
    print("Error : Only Males Allowed")
```

### Output for the lecture values

```text
Error : Only Males Allowed
```

Because:

```python
gender = 'F'
```

the very first condition:

```python
gender == 'M'
```

is false.

Python immediately executes its matching `else`.

### Understanding the nesting

Conceptually:

```text
Is the gender M?
│
├── No  → gender eligibility message
│
└── Yes
    │
    └── Is age between 18 and 55?
        │
        ├── No  → age issue
        │
        └── Yes
            │
            └── Is weight between 50 and 90?
                │
                ├── No  → weight issue
                └── Yes → eligible
```

This demonstrates how nested conditions can identify **which specific validation failed**.

> **Technical clarification:** This is a programming exercise reproducing the instructor's stated conditions, not real-world medical eligibility guidance. Actual blood-donation eligibility depends on medical and regulatory criteria and should be determined by the relevant blood service.

### Chained comparison version

The same range tests could be written as:

```python
if gender == 'M':
    if 18 <= age <= 55:
        if 50 <= weight <= 90:
            print("Can donate blood")
        else:
            print("Weight issue")
    else:
        print("Error : Age issue")
else:
    print("Error : Only Males Allowed")
```

# 11. Leap Year Program

The final screenshot checks whether a year is a leap year.

```python
# Check Year is Leap or Not

year = 1500

if year % 400 == 0:
    print("Leap Year")
elif year % 4 == 0 and year % 100 != 0:
    print("Leap Year")
else:
    print("Not Leap Year")
```

### Output

```text
Not Leap Year
```

## Leap-year rules

For the Gregorian leap-year calculation, a year is a leap year when:

1. it is divisible by `400`, **or**
2. it is divisible by `4` but **not divisible by `100`**.

This gives the logic:

```python
year % 400 == 0
```

or:

```python
year % 4 == 0 and year % 100 != 0
```

### Why is 1500 not a leap year?

Check divisibility:

```python
1500 % 400 == 0
```

is false.

Next:

```python
1500 % 4 == 0
```

is true, but:

```python
1500 % 100 != 0
```

is false because `1500` is divisible by `100`.

Therefore the combined condition is false.

Result:

```text
Not Leap Year
```

### Examples

| Year | Result | Reason |
|---:|---|---|
| 2024 | Leap Year | Divisible by 4 and not by 100 |
| 2025 | Not Leap Year | Not divisible by 4 |
| 1900 | Not Leap Year | Divisible by 100 but not 400 |
| 2000 | Leap Year | Divisible by 400 |

### Equivalent single-condition version

Once you are comfortable with logical operators, the complete rule can be written as:

```python
year = int(input("Enter year: "))

if year % 400 == 0 or (year % 4 == 0 and year % 100 != 0):
    print("Leap Year")
else:
    print("Not Leap Year")
```

The parentheses make the intended grouping easier to read.

# 12. Important Concepts Reinforced in This Lecture

## Relational operators

| Operator | Meaning | Example |
|---|---|---|
| `>` | greater than | `a > b` |
| `<` | less than | `a < b` |
| `>=` | greater than or equal | `age >= 18` |
| `<=` | less than or equal | `age <= 55` |
| `==` | equal to | `m == 2` |
| `!=` | not equal to | `year % 100 != 0` |

Remember:

```python
=
```

means **assignment**, while:

```python
==
```

means **comparison**.

---

## Logical `and`

Use `and` when **all conditions must be true**.

```python
age >= 18 and age <= 55
```

Example:

```text
True and True  → True
True and False → False
False and True → False
False and False → False
```

---

## Logical `or`

Use `or` when **at least one condition must be true**.

```python
m == 4 or m == 6 or m == 9 or m == 11
```

Example:

```text
True or False  → True
False or True  → True
False or False → False
```

---

## Chained comparisons

Python supports mathematical-style chained comparisons:

```python
18 <= age <= 55
```

This is equivalent to:

```python
age >= 18 and age <= 55
```

Similarly:

```python
0 <= n <= 9
```

is equivalent to:

```python
n >= 0 and n <= 9
```

---

## `if-elif-else` executes top to bottom

Consider:

```python
if condition1:
    ...
elif condition2:
    ...
elif condition3:
    ...
else:
    ...
```

Python checks each condition in sequence.

Once one condition is true, its block executes and the remaining branches in that chain are skipped.

---

## Nested `if`

A nested `if` is an `if` statement inside another conditional block.

```python
if condition1:
    if condition2:
        print("Both conditions passed")
```

Use nesting when the second decision should only be considered after the first requirement succeeds.

# 13. Common Beginner Mistakes

### Mistake 1 — Using `=` instead of `==`

Incorrect:

```python
if m = 2:
```

Correct:

```python
if m == 2:
```

`=` assigns a value. `==` compares values.

---

### Mistake 2 — Forgetting the colon

Incorrect:

```python
if age >= 18
    print("Allowed")
```

Correct:

```python
if age >= 18:
    print("Allowed")
```

---

### Mistake 3 — Incorrect indentation

Incorrect:

```python
if age >= 18:
print("Adult")
```

Correct:

```python
if age >= 18:
    print("Adult")
```

Indentation defines Python's code blocks.

---

### Mistake 4 — Using `or` when every condition is required

For a student who must pass **all** subjects, this is wrong:

```python
if m1 >= 35 or m2 >= 35 or m3 >= 35:
```

It would pass the student when only one subject meets the threshold.

Use:

```python
if m1 >= 35 and m2 >= 35 and m3 >= 35:
```

---

### Mistake 5 — Incorrect range logic

Incorrect:

```python
if age >= 18 or age <= 55:
```

For checking whether age is inside the range, this is far too permissive.

Correct:

```python
if age >= 18 and age <= 55:
```

or:

```python
if 18 <= age <= 55:
```

---

### Mistake 6 — Forgetting that `input()` returns text

```python
n = input("Enter number: ")
```

Here `n` is a string.

For numerical comparisons, convert it:

```python
n = int(input("Enter number: "))
```

---

### Mistake 7 — Incorrect leap-year rule

This is incomplete:

```python
if year % 4 == 0:
    print("Leap Year")
```

Century years require special handling.

For example, `1900` is divisible by 4 but is **not** a Gregorian leap year.

Use the full rule:

```python
if year % 400 == 0 or (year % 4 == 0 and year % 100 != 0):
    print("Leap Year")
else:
    print("Not Leap Year")
```

# 16. Key Takeaways

1. Use relational operators such as `>=`, `<=`, `==`, and `!=` to build conditions.
2. Use `and` when **all requirements** must be true.
3. Use `or` when **any one** of several alternatives may be true.
4. Python supports readable chained comparisons such as `18 <= age <= 55`.
5. An `if-elif-else` chain is evaluated from top to bottom and stops at the first matching branch.
6. Nested `if` statements are useful when later decisions depend on earlier validation.
7. `input()` returns a string; use `int()` when integer input is required.
8. Character ranges such as `'A' <= ch <= 'Z'` can classify basic English letters.
9. The modulo operator `%` is essential for divisibility checks such as leap-year calculations.
10. Leap years require the complete `400 / 100 / 4` rule, not only divisibility by 4.
11. Indentation is part of Python syntax and determines which statements belong to each conditional block.
12. When learning conditionals, manually tracing each condition as `True` or `False` is one of the best ways to understand program flow.
