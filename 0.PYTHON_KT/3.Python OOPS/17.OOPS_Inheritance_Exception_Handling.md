## 1. Single inheritance

**Inheritance** allows a child (subclass) to reuse methods and attributes defined in a parent (base class). The syntax `class Second(First)` means `Second` inherits from `First`.

```python
class First:
    def m1(self):
        print("First - m1")

    def m2(self):
        print("First - m2")


class Second(First):
    def m2(self):
        print("Second - m2")

    def m3(self):
        print("Second - m3")


obj = Second()
obj.m1()
obj.m2()
obj.m3()
```

**Output:**

```text
First - m1
Second - m2
Second - m3
```

`m1()` comes from `First`; `m2()` comes from `Second` because the child overrides the parent's method; `m3()` exists only in `Second`. **Important:** The screenshot's earlier `Second.m1()` call produces an `AttributeError` if `Second` does *not* inherit from `First`. Make sure the class declaration is `class Second(First):`, not `class Second:`.

## 2. Method overriding

**Method overriding** means defining a method in a child class with the same name as one in its parent. This lets the child customize inherited behavior. For example, a new phone model may offer a better camera than its parent model.

```python
class Galaxy:
    def camera(self):
        print("12MP camera")


class Note(Galaxy):
    def camera(self):
        print("24MP camera")


old_phone = Galaxy()
new_phone = Note()
old_phone.camera()
new_phone.camera()
```

**Output:**

```text
12MP camera
24MP camera
```

A child can also extend parent behavior rather than replace it completely using `super()`:

```python
class Galaxy:
    def camera(self):
        print("Base camera initialized")


class Note(Galaxy):
    def camera(self):
        super().camera()
        print("24MP camera enabled")


Note().camera()
```

`super()` follows Python's method resolution order; it is not always equivalent to calling a specifically named parent directly.

## 3. Multiple inheritance and Method Resolution Order (MRO)

Python supports inheriting from more than one parent. If multiple classes define a method with the same name, Python uses its **Method Resolution Order** to select which method is called.

```text
      A       B
       \     /
         C

class C(A, B)
```

Lecture example:

```python
class A:
    def m1(self):
        print("A - m1")

    def m2(self):
        print("A - m2")


class B:
    def m2(self):
        print("B - m2")

    def m3(self):
        print("B - m3")


class C(A, B):
    def m1(self):
        print("C - m1")


obj = C()
obj.m1()
obj.m2()
obj.m3()
print([cls.__name__ for cls in C.mro()])
```

**Output:**

```text
C - m1
A - m2
B - m3
['C', 'A', 'B', 'object']
```

| Call | Where Python finds the method | Why |
|---|---|---|
| `obj.m1()` | `C` | Child overrides `A.m1` |
| `obj.m2()` | `A` | `A` precedes `B` in the MRO |
| `obj.m3()` | `B` | Neither `C` nor `A` defines `m3` |

**Key detail:** MRO is not simply “always check parents left to right.” Python computes a consistent linear order using **C3 linearization**, especially important in diamond-shaped inheritance. Inspect it with `C.mro()` or `C.__mro__`. Reversing the bases to `class C(B, A)` would make `B.m2()` win if `C` does not override `m2()`.

## 4. Understanding exceptions

An **exception** is an event raised while Python executes code that disrupts the normal flow unless handled. An unhandled exception normally ends the current program and displays a **traceback** (technical error information). Exceptions are objects instantiated from exception classes, such as `ValueError` and `ZeroDivisionError`.

A simple program without handling:

```python
a = int(input("Enter first num : "))
b = int(input("Enter second num : "))
c = a + b
print(f"Sum = {c}")
```

Valid input:

```text
Enter first num : 12
Enter second num : 13
Sum = 25
```

Invalid input:

```text
Enter first num : abc
ValueError: invalid literal for int() with base 10: 'abc'
```

The last line is the important part of a longer traceback. `int("abc")` raises `ValueError` because `abc` is not a valid integer literal.

## 5. Handling ValueError

Put code that might fail in `try`, and handle the anticipated exception in `except`.

```python
try:
    a = int(input("Enter first num : "))
    b = int(input("Enter second num : "))
    c = a + b
    print(f"Sum = {c}")
except ValueError:
    print("Exception : Input is Invalid")
```

For `12` and `13`, output is `Sum = 25`. For `abc`, output is `Exception : Input is Invalid`, without an unhandled traceback.

**Flow:** execute `try` → if no exception, skip `except` → if a matching exception occurs, stop the remaining statements in `try` and execute that `except` block. The exception is handled only if it matches a handler.

## 6. Handling multiple exception types

One `try` can have multiple `except` clauses, allowing targeted messages for different failures.

```python
try:
    a = int(input("Enter first num : "))
    b = int(input("Enter second num : "))
    c = a / b
    print(f"Quotient = {c}")
except ValueError:
    print("Exception : Input is Invalid")
except ZeroDivisionError:
    print("Exception : Denominator cannot be zero")
```

Examples:

| Inputs | Result |
|---|---|
| `10`, `5` | `Quotient = 2.0` |
| `10`, `0` | `Exception : Denominator cannot be zero` |
| `abc` | `Exception : Input is Invalid` |
| `10`, `3` | `Quotient = 3.3333333333333335` (typical display) |

`/` performs true division and normally produces a `float`. If the second number is zero, Python raises `ZeroDivisionError`.

## 7. List-index division example

The lecture combines three possible failures: invalid integer input, an index outside the list, and division by zero.

```python
# Index:  0  1  2  3  4  5  6  7  8
nums = [3, 8, 9, 0, 4, 6, 5, 2, 0]

try:
    x = int(input("Enter first loc : "))
    y = int(input("Enter second loc : "))

    a = nums[x]
    b = nums[y]

    c = a / b
    print(f"Quotient : {c}")

except ValueError:
    print("Exception : Invalid locs")
except IndexError:
    print("Exception : Out of Bounds")
except ZeroDivisionError:
    print("Exception : cannot divide by 0")
```

**Representative runs:**

| First index | Second index | Explanation | Output |
|---|---|---|---|
| `1` | `4` | `8 / 4` | `Quotient : 2.0` |
| `1` | `3` | `8 / 0` | `Exception : cannot divide by 0` |
| `13` | `34` | `nums[13]` is out of range | `Exception : Out of Bounds` |
| `abc` | — | `int("abc")` fails | `Exception : Invalid locs` |

**Subtle Python behavior:** Negative indices are legal: `nums[-1]` refers to the last element (`0`). If your application requires locations only from `0` through `8`, explicitly validate them instead of relying on `IndexError`.

## 8. Catching and displaying exception messages

Every raised exception object can be converted to a string to obtain its message. The screenshot demonstrates a single general handler:

```python
nums = [3, 8, 9, 0, 4, 6, 5, 2, 0]

try:
    x = int(input("Enter first loc : "))
    y = int(input("Enter second loc : "))

    a = nums[x]
    b = nums[y]

    c = a / b
    print(f"Quotient : {c}")
except Exception as msg:
    print(f"Exception : {msg}")
```

Example error messages:

```text
Exception : invalid literal for int() with base 10: 'abc'
Exception : list index out of range
Exception : division by zero
```

`msg` is a variable referencing the caught exception object; its name can be `error`, `exc`, or another valid identifier. `Exception` catches most ordinary application exceptions, but not every possible Python exception (`KeyboardInterrupt` and `SystemExit`, for example, inherit from `BaseException` directly).

**Best practice:** Prefer specific exception classes when you know which failures to expect. A broad `except Exception` can hide programming defects if you silently suppress errors; log or re-raise unexpected failures as appropriate.

## 9. Practical improvements

### 9.1 Group related exception types

```python
try:
    number = int(input("Enter an integer: "))
    print(100 / number)
except (ValueError, ZeroDivisionError) as error:
    print(f"Unable to calculate: {error}")
```

### 9.2 `else` and `finally`

```python
try:
    number = int(input("Enter a nonzero integer: "))
    result = 100 / number
except ValueError:
    print("Please enter a valid integer")
except ZeroDivisionError:
    print("Zero is not allowed")
else:
    print(f"Result: {result}")
finally:
    print("Calculation attempt finished")
```

`else` runs when the `try` block completes without an exception. `finally` runs during normal exception handling or normal completion (with special cases such as abrupt process termination).

### 9.3 Validate indices to reject negative values

```python
nums = [3, 8, 9, 0, 4, 6, 5, 2, 0]

try:
    x = int(input("First index: "))
    y = int(input("Second index: "))

    if not (0 <= x < len(nums) and 0 <= y < len(nums)):
        raise IndexError("Indices must be between 0 and 8")

    print(f"Quotient: {nums[x] / nums[y]}")
except ValueError:
    print("Enter integer indices only")
except IndexError as error:
    print(f"Invalid index: {error}")
except ZeroDivisionError:
    print("Cannot divide by zero")
```

### 9.4 Useful debugging guidance

- **`AttributeError`**: a method or attribute is not found on the object/class; verify the inheritance declaration and spelling.
- **`NameError`**: a referenced name does not exist in the current scope; check class/variable names.
- **`ValueError`**: a value has the right general type but is inappropriate for an operation (e.g., `int("abc")`).
- **`IndexError`**: a sequence index is out of range.
- **`ZeroDivisionError`**: an attempted division has a zero denominator.
- Read tracebacks **from the bottom up**: the last line identifies the exception type and message, and the preceding lines show where it happened.

### Quick reference

| Concept | Python syntax | Purpose |
|---|---|---|
| Single inheritance | `class Child(Parent):` | Reuse parent behavior |
| Multiple inheritance | `class C(A, B):` | Inherit from several bases |
| Overriding | `def method(self):` in child | Customize inherited behavior |
| Parent/cooperative call | `super().method()` | Continue according to MRO |
| Inspect MRO | `C.mro()` | See lookup order |
| Try block | `try:` | Execute potentially failing code |
| Specific handler | `except ValueError:` | Handle one expected exception |
| Multiple handlers | several `except` clauses | Handle different errors |
| Exception message | `except Exception as error:` | Access caught exception object |
| Success-only branch | `else:` | Run if `try` succeeds |
| Cleanup branch | `finally:` | Run cleanup code |
