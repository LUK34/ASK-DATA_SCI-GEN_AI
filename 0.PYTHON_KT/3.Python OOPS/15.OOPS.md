## 1. From functions to objects

The lecture contrasts storing information in variables and processing it with functions against grouping information and behavior inside classes.

### Standalone functions

```python
bank_name = "HDFC"

def show_bank():
    print(bank_name)

show_bank()
```

**Output:**

```text
HDFC
```

This is a simple procedural example. **Technical note:** The screenshot labels standalone functions as *functional programming*, but using functions alone does not necessarily mean a program follows the functional programming paradigm. Functional programming emphasizes function composition, limited side effects, and often immutable data.

### Object-oriented approach

```python
class BankAccount:
    bank_name = "HDFC"  # Shared class attribute

    def __init__(self, account_number, customer_name, balance):
        self.account_number = account_number
        self.customer_name = customer_name
        self.balance = balance

account1 = BankAccount(101, "Amar", 5000)
account2 = BankAccount(102, "Diya", 8000)
account3 = BankAccount(103, "Sam", 3000)

print(account1.bank_name)
print(account1.account_number, account1.customer_name, account1.balance)
print(account2.account_number, account2.customer_name, account2.balance)
```

**Output:**

```text
HDFC
101 Amar 5000
102 Diya 8000
```

Here, `bank_name` belongs to the class, while each account object stores its own account number, name, and balance.

## 2. Class (static) variables vs instance (dynamic) variables

The lecture uses the terms **static variables** and **dynamic variables**. In Python, the standard terms are **class attributes** and **instance attributes**.

| Feature | Class attribute | Instance attribute |
| --- | --- | --- |
| Declared | Usually in the class body | Usually via `self` in `__init__` |
| Associated with | Class | Individual instance |
| Typical purpose | Shared defaults or common data | Object-specific state |
| Access | `ClassName.attribute` or `obj.attribute` | `obj.attribute` |
| Example | Bank name | Account number, balance |

```python
class Customer:
    bank_name = "HDFC"  # Class attribute

    def __init__(self, number, name):
        self.number = number  # Instance attribute
        self.name = name      # Instance attribute

first = Customer(101, "Amar")
second = Customer(102, "Diya")

print(Customer.bank_name)
print(first.number)
print(second.number)
```

**Output:**

```text
HDFC
101
102
```

**Important corrections:** Class attributes are not automatically immutable or private. Instance attributes are not automatically access-restricted. Python's memory behavior is more nuanced than “one allocation” versus “one allocation per object”; class attributes reside in the class namespace, and instance attributes generally reside in each object's state. Avoid using mutable class attributes such as `[]` as per-instance storage unless sharing is intentional.

## 3. Methods: the screenshot's static and dynamic examples

The lecturer demonstrates a method with no `self`, called using the class name, and a method with `self`, called using an object.

### 3.1 Lecture code (faithfully reconstructed)

```python
class Test:
    def m1():
        print("static method")
        return

    def m2(self):
        print("dynamic method")
        return

Test.m1()

obj = Test()
obj.m2()
```

**Output:**

```text
static method
dynamic method
```

This works for the exact calls shown. However, `m1` is **not formally declared as a Python static method**. It is an ordinary function stored in the class namespace that happens to be callable as `Test.m1()` without an instance.

Calling `obj.m1()` would raise `TypeError` because Python binds the instance automatically to a regular method.

### 3.2 Recommended Python syntax: `@staticmethod`

```python
class Test:
    @staticmethod
    def m1():
        print("static method")

    def m2(self):
        print("dynamic method")

Test.m1()
obj = Test()
obj.m2()
```

**Output:**

```text
static method
dynamic method
```

The `@staticmethod` decorator makes the intent explicit and allows calling `Test.m1()` or `obj.m1()` without automatic `self` binding.

### 3.3 Understanding `self`

```python
class Greeter:
    def say_hello(self, name):
        print(f"Hello, {name}!")

g = Greeter()
g.say_hello("Amar")
```

**Output:**

```text
Hello, Amar!
```

`self` is the conventional name for the current instance. When you call `g.say_hello("Amar")`, Python supplies `g` as the first argument automatically. `self` is not a reserved keyword, but you should follow this convention.

## 4. Four method patterns shown in the lecture

The screenshots classify methods by whether they accept arguments and return a value. The examples below preserve that teaching pattern, using proper `@staticmethod` declarations.

### 4.1 No arguments and no explicit return value

```python
class Clear:
    @staticmethod
    def all():
        print("Clear all")
        return

Clear.all()
```

**Output:**

```text
Clear all
```

An empty `return` returns `None` implicitly. It does not return a useful value.

### 4.2 Arguments and no explicit return value

```python
class Add:
    @staticmethod
    def nums(a, b):
        print(f"Sum = {a + b}")
        return

Add.nums(10, 20)
```

**Output:**

```text
Sum = 30
```

### 4.3 Arguments and a return value

```python
class Add:
    @staticmethod
    def nums(a, b):
        return a + b

res = Add.nums(10, 20)
print(f"Sum = {res}")
```

**Output:**

```text
Sum = 30
```

### 4.4 No arguments and a return value

```python
class Get:
    @staticmethod
    def PI():
        return 3.142

pi = Get.PI()
print(f"PI value = {pi}")
```

**Output:**

```text
PI value = 3.142
```

**Professional note:** In real applications, Python's `math.pi` is more accurate than the approximate `3.142` used in this exercise.

## 5. Constructors and the `__init__` method

The lecture adds `__init__` to show what happens when an object is created.

```python
class Test:
    @staticmethod
    def m1():
        print("Static Method")

    def m2(self):
        print("Dynamic method")

    def __init__(self):
        print("Constructor")

Test.m1()
obj = Test()
obj.m2()
```

**Output:**

```text
Static Method
Constructor
Dynamic method
```

**Execution order:**

1. `Test.m1()` prints `Static Method`.
2. `Test()` creates a new instance and calls its `__init__`, which prints `Constructor`.
3. `obj.m2()` prints `Dynamic method`.

`__init__` is commonly called a constructor in beginner courses, but technically it is an **initializer**. The `__new__` method is responsible for creating the instance. `__init__` initializes it and must return `None`.

### Practical initializer with parameters

```python
class Student:
    def __init__(self, student_id, name):
        self.student_id = student_id
        self.name = name

    def display(self):
        print(f"{self.student_id}: {self.name}")

student = Student(101, "Amar")
student.display()
```

**Output:**

```text
101: Amar
```

## 6. Exercise shown in the screenshot: `Check` class

The screenshot shows method stubs named `is_even` and `is_alphabet`, called with `13` and `'s'`. Since the screenshot contains only `return` placeholders, these functions would print nothing and return `None` as written.

### Complete, working implementation

```python
class Check:
    def is_even(self, n):
        return n % 2 == 0

    def is_alphabet(self, ch):
        return isinstance(ch, str) and len(ch) == 1 and ch.isalpha()

obj = Check()
print(obj.is_even(13))
print(obj.is_alphabet('s'))
```

**Output:**

```text
False
True
```

- `%` calculates the remainder; an even integer has remainder `0` when divided by `2`.
- `isalpha()` checks whether the string contains alphabetic characters.
- `len(ch) == 1` ensures we are checking one character rather than a whole word.

## 7. Public class attributes and double-underscore attributes

### 7.1 Public class attribute

```python
class Test:
    x = 10  # Public class attribute

print(f"x value : {Test.x}")
```

**Output:**

```text
x value : 10
```

### 7.2 Why direct access to `__y` fails

The screenshot demonstrates an error like the following:

```python
class Test:
    x = 10
    __y = 10

print(f"x value : {Test.x}")
print(f"y value : {Test.__y}")
```

**Result:**

```text
x value : 10
AttributeError: type object 'Test' has no attribute '__y'
```

Why? Python **name-mangles** double-leading-underscore names inside class definitions. Internally, `__y` is stored under a name such as `_Test__y`. This helps avoid accidental name collisions in subclasses, but is **not strong privacy or a security boundary**.

### 7.3 The lecture's getter-style solution

```python
class Test:
    x = 10
    __y = 20

    def get_y():
        return Test.__y

print(f"x value : {Test.x}")
print(f"y value : {Test.get_y()}")
```

**Output:**

```text
x value : 10
y value : 20
```

This matches the lecture's approach and works when called using the class name. A more explicit version would use `@staticmethod`, or use `@classmethod` with `cls`:

```python
class Test:
    x = 10
    __y = 20

    @classmethod
    def get_y(cls):
        return cls.__y

print(f"x value : {Test.x}")
print(f"y value : {Test.get_y()}")
```

**Output:**

```text
x value : 10
y value : 20
```

**Why `@classmethod`?** It receives the class as `cls`, so it can refer to class-specific state and generally behaves better with inheritance than hard-coding `Test`.

## 8. Static methods vs instance methods vs class methods

| Kind | Declaration | First automatic argument | Typical usage |
| --- | --- | --- | --- |
| Instance method | `def method(self):` | Instance (`self`) | Operate on object state |
| Static method | `@staticmethod` | None | Utility logic related to the class |
| Class method | `@classmethod` | Class (`cls`) | Operate on class state or create alternative constructors |

```python
class Example:
    category = "Python"

    def __init__(self, name):
        self.name = name

    def instance_method(self):
        return self.name

    @staticmethod
    def static_method(a, b):
        return a + b

    @classmethod
    def class_method(cls):
        return cls.category

obj = Example("Amar")
print(obj.instance_method())
print(Example.static_method(10, 20))
print(Example.class_method())
```

**Output:**

```text
Amar
30
Python
```

## 9. Encapsulation and practical security considerations

The lecture uses a banking example to introduce restricted access to account details. Encapsulation means grouping state and behavior and controlling how callers interact with that state.

```python
class BankAccount:
    bank_name = "HDFC"

    def __init__(self, account_number, balance):
        self.account_number = account_number
        self.__balance = balance

    def get_balance(self):
        return self.__balance

    def deposit(self, amount):
        if amount <= 0:
            raise ValueError("Deposit must be positive")
        self.__balance += amount

account = BankAccount(101, 5000)
account.deposit(1500)
print(account.get_balance())
```

**Output:**

```text
6500
```

This demonstrates a controlled interface, **not secure storage**. Name mangling does not protect sensitive financial data from a determined caller. Real banking systems also require authentication, authorization, auditing, encryption, and secure handling of credentials. Never store real PINs or passwords in plaintext class attributes.

## 10. Common mistakes and troubleshooting

| Mistake | What happens | Correction |
| --- | --- | --- |
| Calling `obj.m1()` when `m1` lacks `self` and `@staticmethod` | `TypeError` due to implicit instance binding | Add `@staticmethod` or an appropriate `self` parameter |
| Calling `Test.__y` | `AttributeError` | Expose an intentional getter or property |
| Forgetting `self` in an instance method | Method call may receive unexpected arguments | Declare `def method(self, ...)` |
| Expecting `return` with no expression to produce a result | Returns `None` | Return a value explicitly |
| Assuming class variables are private | Unexpected access or modification | Use deliberate APIs and validation |
| Using a mutable class attribute for individual object state | Objects may share the same list or dictionary | Initialize mutable state in `__init__` |

## 12. Quick revision

- **Class:** Blueprint that groups attributes and methods.
- **Object / instance:** An individual instance created from a class.
- **Class attribute:** Attribute stored on the class, commonly used for shared information.
- **Instance attribute:** Attribute stored on a particular object, commonly created using `self`.
- **Instance method:** Regular method that receives the instance as `self` when invoked through an instance.
- **Static method:** Method decorated with `@staticmethod`; receives no implicit `self` or `cls`.
- **Class method:** Method decorated with `@classmethod`; receives the class as `cls`.
- **`__init__`:** Initializer invoked during ordinary object construction.
- **`__name`:** Triggers name mangling inside a class; does not create absolute privacy.
- **`return`:** Sends a result back to the caller; an empty `return` produces `None`.
