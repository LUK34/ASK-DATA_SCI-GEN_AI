## 1. Private-style class attributes and class-level getters/setters

The first screenshot defines two class attributes, `__x` and `__y`, and uses methods to read and change them. The double underscore triggers **name mangling**: Python internally changes `__x` to `_Test__x`. This discourages accidental access, but is **not strict security or true access control**.

### Lecture example (copy and run)

```python
class Test:
    __x = 10
    __y = 20

    def get_x():
        return Test.__x

    def get_y():
        return Test.__y

    def set_x(x):
        Test.__x = x

    def set_y(y):
        Test.__y = y


print(f"x value : {Test.get_x()}")
print(f"y value : {Test.get_y()}")

Test.set_x(15)
Test.set_y(25)

print(f"x value : {Test.get_x()}")
print(f"y value : {Test.get_y()}")
```

**Expected output**

```text
x value : 10
y value : 20
x value : 15
y value : 25
```

**How it works:** `Test.get_x()` retrieves the class attribute. `Test.set_x(15)` replaces the value shared at the class level. No instance is created. These lecture methods work when called through the class because they do not accept `self`, but they are **not decorated static methods**. Calling `Test().get_x()` would pass an implicit instance and raise `TypeError`.

### Recommended modern Python form

Declare class-level utility methods explicitly with `@staticmethod`:

```python
class Test:
    __x = 10
    __y = 20

    @staticmethod
    def get_x():
        return Test.__x

    @staticmethod
    def get_y():
        return Test.__y

    @staticmethod
    def set_x(value):
        Test.__x = value

    @staticmethod
    def set_y(value):
        Test.__y = value


print(Test.get_x(), Test.get_y())  # 10 20
Test.set_x(15)
Test.set_y(25)
print(Test.get_x(), Test.get_y())  # 15 25
```

For subclass-aware class-level operations, `@classmethod` with `cls` is often a better fit.

### Errors shown in the lecture

**AttributeError** occurs when code tries `Test.__x` directly outside the class:

```python
# print(Test.__x)  # AttributeError: type object 'Test' has no attribute '__x'
print(Test.get_x())  # Correct: 10 (before updating)
```

**NameError** occurs when `Text.get_y()` is typed instead of `Test.get_y()`:

```python
# print(Text.get_y())  # NameError: name 'Text' is not defined
print(Test.get_y())    # Correct
```

The exact numeric value depends on whether a setter has already run.

## 2. Instance attributes: employee example

A class describes the structure of an employee. Each call to `Employee(...)` creates a **different object** with its own values. The constructor `__init__` receives those values and stores them on `self`.

### Lecture example

```python
class Employee:
    def __init__(self, num, name, salary):
        self.__num = num
        self.__name = name
        self.__salary = salary

    def details(self):
        print(f"Details : {self.__num}, {self.__name}, {self.__salary}")


e1 = Employee(101, "Amar", 45000)
e2 = Employee(102, "Annie", 50000)
e3 = Employee(103, "Harin", 55000)

e1.details()
e2.details()
e3.details()
```

**Expected output**

```text
Details : 101, Amar, 45000
Details : 102, Annie, 50000
Details : 103, Harin, 55000
```

### Object diagram

```text
Employee class
    |
    +-- e1 ---> Employee(num=101, name="Amar", salary=45000)
    |
    +-- e2 ---> Employee(num=102, name="Annie", salary=50000)
    |
    +-- e3 ---> Employee(num=103, name="Harin", salary=55000)
```

The screenshot labels the objects with illustrative identifiers such as `6748`, `6738` and `8869`. These are **not guaranteed Python memory addresses**. Object identities are runtime-dependent. Unlike the class-level values in Section 1, updating `e1`'s attributes does not automatically update `e2` or `e3`.

## 3. Instance-level private-style attributes with getter and setter

This screenshot moves from shared class-level state to state belonging to **one instance**.

```python
class Test:
    def __init__(self):
        self.__x = 10

    def get_x(self):
        return self.__x

    def set_x(self, x):
        self.__x = x


obj = Test()
print(f"x value : {obj.get_x()}")
obj.set_x(15)
print(f"x value : {obj.get_x()}")
```

**Output**

```text
x value : 10
x value : 15
```

**Explanation:** `self` refers to the object on which the method is called. `obj.get_x()` reads that object's value; `obj.set_x(15)` updates it. The `__x` name is mangled to `_Test__x`, not encrypted.

## 5. Adding deposits

A deposit adds money to the existing balance.

```python
class Account:
    def __init__(self, amt):
        self.__balance = amt

    def get_balance(self):
        return self.__balance

    def deposit(self, amt):
        self.__balance = self.__balance + amt
        print(f"{amt} is deposited")


amt = int(input("Enter initial bal : "))
acc = Account(amt)
print(f"Balance in account is : {acc.get_balance()}")

amt = int(input("Enter deposit amt : "))
acc.deposit(amt)
print(f"Balance after deposit : {acc.get_balance()}")
```

**Example interaction**

```text
Enter initial bal : 5000
Balance in account is : 5000
Enter deposit amt : 3000
3000 is deposited
Balance after deposit : 8000
```

**Formula:** `new_balance = old_balance + deposit`.

## 6. Adding withdrawals: complete lecture program

A withdrawal is permitted when the requested amount is no greater than the current balance.

```python
class Account:
    def __init__(self, amt):
        self.__balance = amt

    def get_balance(self):
        return self.__balance

    def deposit(self, amt):
        self.__balance = self.__balance + amt
        print(f"{amt} is deposited")

    def withdraw(self, amt):
        if amt <= self.__balance:
            print(f"Collect cash : {amt}")
            self.__balance = self.__balance - amt
        else:
            print("Error : Low Balance in Account")


amt = int(input("Enter initial bal : "))
acc = Account(amt)
print(f"Balance in account is : {acc.get_balance()}")

amt = int(input("Enter deposit amt : "))
acc.deposit(amt)
print(f"Balance after deposit : {acc.get_balance()}")

amt = int(input("Enter withdraw amt : "))
acc.withdraw(amt)
print(f"Balance after withdraw : {acc.get_balance()}")
```

**Screenshot's example interaction**

```text
Enter initial bal : 5000
Balance in account is : 5000
Enter deposit amt : 2000
2000 is deposited
Balance after deposit : 7000
Enter withdraw amt : 4500
Collect cash : 4500
Balance after withdraw : 2500
```

**Balance walkthrough**

| Operation | Calculation | Balance |
| --- | --- | ---: |
| Open account | Initial amount | 5000 |
| Deposit | 5000 + 2000 | 7000 |
| Withdraw | 7000 - 4500 | 2500 |

If the withdrawal amount exceeds the balance, the method prints `Error : Low Balance in Account` and leaves the balance unchanged.

### Important limitation of the lecture example

The lecture code accepts **negative deposits and withdrawals**. For example, withdrawing `-100` passes `amt <= balance` and *increases* the balance by 100. This is a teaching demonstration, **not production-ready banking software**. Real systems also need authentication, authorization, durable storage, audit trails, concurrency control, and safe monetary arithmetic.

## 7. Safer practice version: validation and decimal arithmetic

This improved example uses `Decimal` to represent monetary amounts and validates that deposits and withdrawals are positive.

```python
from decimal import Decimal, InvalidOperation


class Account:
    def __init__(self, initial_balance):
        self.__balance = Decimal(str(initial_balance))
        if not self.__balance.is_finite() or self.__balance < 0:
            raise ValueError("Initial balance must be non-negative and finite")

    def get_balance(self):
        return self.__balance

    def deposit(self, amount):
        value = Decimal(str(amount))
        if not value.is_finite() or value <= 0:
            raise ValueError("Deposit must be positive and finite")
        self.__balance += value

    def withdraw(self, amount):
        value = Decimal(str(amount))
        if not value.is_finite() or value <= 0:
            raise ValueError("Withdrawal must be positive and finite")
        if value > self.__balance:
            raise ValueError("Insufficient funds")
        self.__balance -= value


account = Account("5000.00")
account.deposit("2000.00")
account.withdraw("4500.00")
print(f"Final balance: {account.get_balance():.2f}")
```

**Output**

```text
Final balance: 2500.00
```

This is safer for learning, but still not a production banking implementation. Actual financial software must also enforce currency-specific precision and rounding rules.

## 8. Key concepts compared

| Concept | Meaning | Example |
| --- | --- | --- |
| Class | Blueprint for objects | `class Employee:` |
| Object | An instance of a class | `e1 = Employee(...)` |
| Constructor initializer | Sets up instance state | `__init__(self, ...)` |
| Class attribute | Associated with the class, often shared | `Test.__x` (within class) |
| Instance attribute | Stored on a specific object | `self.__balance` |
| Getter | Reads a value through a method | `get_balance()` |
| Setter | Changes a value through a method | `set_x(15)` |
| Encapsulation | Groups data and operations behind an interface | `Account.deposit()` |
| Name mangling | Rewrites double-underscore names to reduce accidental clashes/access | `__balance` |
| `@staticmethod` | Method without implicit `self` or `cls` | `@staticmethod def get_x(): ...` |

## 9. Common mistakes and debugging

1. **Using `Test.__x` outside the class:** Double-underscore names are mangled. Prefer an intended getter or property.
2. **Typing `Text` instead of `Test`:** Python identifiers are exact and case-sensitive; this raises `NameError`.
3. **Omitting `self` in an instance method:** Calling it through an object can produce `TypeError`.
4. **Assuming all methods without `self` are automatically static methods:** Use `@staticmethod` to express that intent explicitly.
5. **Treating `__balance` as secure/private:** It is name-mangled, not protected against deliberate access.
6. **Accepting negative transaction amounts:** Validate all amounts before updating a balance.
7. **Using `float` for money:** Prefer `Decimal` with explicit currency and rounding policies.
8. **Using `return` without a value:** This returns `None`; it is optional at the end of a method that does not need to return a result.

## 11. Quick revision

- **Class attributes** belong to the class; **instance attributes** belong to individual objects.
- `__init__` initializes a new object's attributes; it is called during object creation.
- `self` gives instance methods access to the current object.
- Getters and setters provide a controlled interface to data.
- Double underscores perform **name mangling**, not strong privacy enforcement.
- Deposit adds to balance; withdrawal subtracts only when sufficient funds exist.
- Always validate transaction inputs before changing financial state.
