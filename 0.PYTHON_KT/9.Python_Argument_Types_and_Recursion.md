# 1. Quick Review: Functions with Arguments and Return Values

A function can accept input through parameters, process those values, and return a result.

```python
def add(a, b):
    c = a + b
    return c

res = add(10, 20)
print(f"Sum = {res}")
```

Output:

```text
Sum = 30
```

### Flow

```text
add(10, 20)
     |
     v
a = 10, b = 20
     |
     v
c = a + b
     |
     v
c = 30
     |
     v
return 30
     |
     v
res = 30
```

`return` sends a value back to the location from which the function was called.

# 2. More Examples of Returning Values

## Checking whether a number is even

```python
def is_even(n):
    if n % 2 == 0:
        return f"{n} is even"
    else:
        return f"{n} is not even"

msg = is_even(13)
print(msg)
```

Output:

```text
13 is not even
```

The expression:

```python
n % 2 == 0
```

checks whether the remainder after division by `2` is zero.

---

## Checking whether a character is an alphabet

```python
def is_alphabet(ch):
    if (ch >= 'A' and ch <= 'Z') or (ch >= 'a' and ch <= 'z'):
        return f"{ch} is alphabet"
    else:
        return f"{ch} is not alphabet"

msg = is_alphabet('H')
print(msg)
```

Output:

```text
H is alphabet
```

A more idiomatic Python alternative is:

```python
def is_alphabet(ch):
    if ch.isalpha():
        return f"{ch} is alphabet"
    return f"{ch} is not alphabet"
```

> The first version is useful for understanding comparisons and Boolean operators. The second uses Python's built-in string functionality.

# 3. Factorial Using a Function

The factorial of a positive integer is the product of all positive integers from `1` through that number.

For example:

```text
5! = 5 × 4 × 3 × 2 × 1
   = 120
```

Python implementation:

```python
def factorial(n):
    fact = 1

    for i in range(1, n + 1):
        fact = fact * i

    return fact

res = factorial(5)
print(f"Factorial : {res}")
```

Output:

```text
Factorial : 120
```

### Iteration walkthrough

For `factorial(5)`:

| `i` | Calculation | `fact` |
|---:|---|---:|
| Initial | `fact = 1` | 1 |
| 1 | `1 * 1` | 1 |
| 2 | `1 * 2` | 2 |
| 3 | `2 * 3` | 6 |
| 4 | `6 * 4` | 24 |
| 5 | `24 * 5` | 120 |

Finally:

```python
return fact
```

returns `120`.

# 4. Argument Types in Python Functions

The lecture introduces four ways of supplying arguments:

| Type | Main idea |
|---|---|
| Required arguments | Values must be supplied for required parameters |
| Default arguments | Parameters already have fallback values |
| Keyword arguments | Values are supplied using parameter names |
| Variable arguments | Accept zero or more positional values using `*args` |

---

# 5. Required Arguments

Consider:

```python
def test(a, b, c):
    print(a, b, c)
    return
```

Here, `a`, `b`, and `c` do not have default values. Therefore, all three are required when the function is called.

Valid calls:

```python
test(10, 20, 30)
test(10, 23.45, "abc")
```

Possible output:

```text
10 20 30
10 23.45 abc
```

Python is dynamically typed, so the arguments do not all need to contain the same type of value.

## Missing required arguments

This call is invalid:

```python
test(10)
```

Only `a` receives a value. Python still needs values for `b` and `c`, so it raises a `TypeError` similar to:

```text
TypeError: test() missing 2 required positional arguments: 'b' and 'c'
```

### Key rule

> A parameter without a default value must receive a value when the function is called, unless it is otherwise satisfied through a compatible argument-passing mechanism.

---

# 6. Default Arguments

A parameter can be assigned a default value in the function definition.

```python
def test(a=10, b=20, c=30):
    print(a, b, c)
    return
```

Now all three parameters have defaults.

## Call without arguments

```python
test()
```

Output:

```text
10 20 30
```

Because no values were supplied, Python uses all the defaults.

## Override one default

```python
test(15)
```

Output:

```text
15 20 30
```

The positional argument `15` replaces the default for `a`; `b` and `c` retain their defaults.

## Override every default

```python
test(12, 23.45, "abc")
```

Output:

```text
12 23.45 abc
```

### Important concept

Default values are **fallback values**. They are used only when the caller does not supply another value for that parameter.

---

# 7. Mixing Required and Default Parameters

Python allows required and default parameters in the same function, but positional parameters without defaults must come before positional parameters with defaults.

Correct:

```python
def employee(name, department="IT"):
    print(name, department)
```

Incorrect:

```python
def employee(name="Unknown", department):
    pass
```

The second definition causes a syntax error because a required positional parameter follows a default positional parameter.

---

# 8. Keyword Arguments

Normally, positional arguments are assigned according to their position.

```python
def data(name, age):
    print(f"Name : {name}")
    print(f"Age : {age}")
    return


data("Amar", 23)
```

Output:

```text
Name : Amar
Age : 23
```

The mapping is:

```text
"Amar" -> name
23     -> age
```

With keyword arguments, the parameter name is explicitly written in the call:

```python
data(age=21, name="Annie")
```

Output:

```text
Name : Annie
Age : 21
```

Although `age` appears before `name` in the function call, Python knows exactly where each value belongs because the names are specified.

### Main advantage

Keyword arguments make calls more descriptive and allow values to be supplied without relying solely on positional order.

For example:

```python
create_user(name="John", age=30, active=True)
```

can be easier to understand than:

```python
create_user("John", 30, True)
```

---

# 9. Variable-Length Arguments (`*args`)

Sometimes we do not know in advance how many positional arguments a function will receive.

Python provides variable-length positional arguments using `*`.

Lecture example:

```python
def data(*nums):
    print(nums)
    return


data()
data(10, 20)
data(10, 20, 30)
data(10, 20, 30, 40, 50)
```

Output:

```text
()
(10, 20)
(10, 20, 30)
(10, 20, 30, 40, 50)
```

## What does `*nums` mean?

```python
def data(*nums):
```

means:

> Collect all additional positional arguments supplied to the function and place them into `nums`.

Inside the function, `nums` is a **tuple**.

Therefore:

```python
data(10, 20, 30)
```

results in approximately:

```python
nums = (10, 20, 30)
```

---

# 10. `*args` Is a Convention

The special behavior comes from the `*`, not from the word `args`.

These are both valid:

```python
def data(*nums):
    print(nums)
```

```python
def data(*args):
    print(args)
```

`args` is simply the conventional name used by Python developers for arbitrary positional arguments.

---

# 11. Processing Values Received Through `*args`

Because the arguments are stored in a tuple, we can loop through them.

```python
def display(*values):
    for value in values:
        print(value)


display(10, 20, 30)
```

Output:

```text
10
20
30
```

We can also calculate their total:

```python
def total(*nums):
    result = 0

    for num in nums:
        result += num

    return result


print(total(10, 20, 30, 40))
```

Output:

```text
100
```

Python also provides the built-in `sum()` function:

```python
def total(*nums):
    return sum(nums)
```

# 12. Comparison of the Four Argument Types

### Required arguments

```python
def test(a, b, c):
    print(a, b, c)

test(10, 20, 30)
```

All required parameters need values.

### Default arguments

```python
def test(a=10, b=20, c=30):
    print(a, b, c)

test()
test(15)
```

Missing values are replaced by defaults.

### Keyword arguments

```python
def data(name, age):
    print(name, age)

data(age=21, name="Annie")
```

Parameter names explicitly determine the mapping.

### Variable-length arguments

```python
def data(*nums):
    print(nums)

data(10, 20, 30, 40)
```

Any number of positional arguments can be collected into a tuple.

# 13. Important Terminology: Parameter vs Argument

These terms are closely related but not identical.

```python
def add(a, b):
    return a + b

add(10, 20)
```

In the function definition:

```python
a
b
```

are **parameters**.

In the function call:

```python
10
20
```

are **arguments**.

A useful memory rule is:

```text
Parameter -> variable in the function definition
Argument  -> actual value supplied in the function call
```

# 14. Introduction to Recursion

A **recursive function** is a function that calls itself.

Lecture example:

```python
def test(n):
    print(n)

    if n > 1:
        test(n - 1)

    print(n)
    return


test(4)
```

The important line is:

```python
test(n - 1)
```

The function `test()` is calling itself with a smaller value.

---

# 15. Understanding the Recursive Calls

Start with:

```python
test(4)
```

The first call prints:

```text
4
```

Since:

```python
4 > 1
```

is `True`, Python calls:

```python
test(3)
```

That call prints `3` and calls:

```python
test(2)
```

Then `test(2)` prints `2` and calls:

```python
test(1)
```

For `test(1)`:

```python
1 > 1
```

is `False`, so no additional recursive call occurs.

This is the point where the recursion begins returning to previous calls.

---

# 16. Why Values Print Again After Recursion

The function contains two print statements:

```python
def test(n):
    print(n)          # before recursive call

    if n > 1:
        test(n - 1)

    print(n)          # after recursive call
```

The first `print(n)` executes while recursion is going **down**.

The second executes while recursion is **unwinding** back through the previous function calls.

For:

```python
test(4)
```

the output is:

```text
4
3
2
1
1
2
3
4
```

---

# 17. Visualizing the Recursion

The call sequence goes downward:

```text
test(4)
   |
   +--> test(3)
           |
           +--> test(2)
                   |
                   +--> test(1)
```

Each function call is temporarily waiting for the deeper call to finish.

Once `test(1)` finishes, execution returns in reverse order:

```text
test(1) finishes
    |
    v
test(2) continues
    |
    v
test(3) continues
    |
    v
test(4) continues
```

This behavior is closely related to the **call stack**.

---

# 18. The Base Case

Every practical recursive function needs a condition that eventually stops additional recursive calls.

In the lecture example:

```python
if n > 1:
    test(n - 1)
```

`n` keeps decreasing:

```text
4 -> 3 -> 2 -> 1
```

At `1`, the condition becomes false, so recursion stops growing.

This stopping condition is commonly called the **base case**.

Without an appropriate stopping condition, a recursive function can continue until Python raises a `RecursionError`.

Example of a bad recursive function:

```python
def test():
    test()


test()
```

There is nothing that tells the function when to stop.

# 19. Recursive Factorial

The factorial example shown earlier used a loop:

```python
def factorial(n):
    fact = 1

    for i in range(1, n + 1):
        fact *= i

    return fact
```

Factorial can also demonstrate recursion naturally because:

```text
5! = 5 × 4!
4! = 4 × 3!
3! = 3 × 2!
2! = 2 × 1!
1! = 1
```

Python version:

```python
def factorial(n):
    if n <= 1:
        return 1

    return n * factorial(n - 1)


print(factorial(5))
```

Output:

```text
120
```

Conceptually:

```text
factorial(5)
= 5 * factorial(4)
= 5 * 4 * factorial(3)
= 5 * 4 * 3 * factorial(2)
= 5 * 4 * 3 * 2 * factorial(1)
= 5 * 4 * 3 * 2 * 1
= 120
```

---

# 20. Loop vs Recursion

Both loops and recursion can repeat operations, but they work differently.

| Loop | Recursion |
|---|---|
| Repeats using `for` or `while` | Function calls itself |
| Usually straightforward for simple repetition | Useful when a problem naturally breaks into smaller versions of itself |
| Does not create a new function call for each iteration | Each recursive call creates another call-stack frame |
| Often more memory-efficient in Python | Can be elegant but has recursion-depth limitations |

For simple counting or accumulation, loops are often clearer in Python. Recursion is especially useful for learning and for naturally recursive structures such as trees and nested structures.

# 21. Common Beginner Mistakes

## Mistake 1 — Calling a function without all required arguments

```python
def test(a, b, c):
    print(a, b, c)


test(10)
```

This fails because `b` and `c` have no values.

---

## Mistake 2 — Confusing default arguments with required arguments

```python
def test(a=10, b=20, c=30):
    print(a, b, c)
```

Here `test()` is valid because defaults exist.

---

## Mistake 3 — Thinking keyword arguments must follow declaration order

```python
data(age=21, name="Annie")
```

This is valid because each value explicitly names its destination parameter.

---

## Mistake 4 — Thinking `*args` produces a list

```python
def data(*args):
    print(type(args))
```

The collected value is a tuple:

```text
<class 'tuple'>
```

---

## Mistake 5 — Forgetting the recursion stopping condition

A recursive call must eventually reach a condition where no further recursive call is made.

# 24. Final Summary

The central ideas from this lecture are:

```text
FUNCTION ARGUMENTS
|
+-- Required arguments
|      Values must be supplied
|
+-- Default arguments
|      Use predefined values when omitted
|
+-- Keyword arguments
|      parameter=value explicitly identifies the destination
|
+-- Variable-length arguments
       *args collects zero or more positional arguments into a tuple
```

And for recursion:

```text
Function calls itself
        |
        v
Problem becomes smaller
        |
        v
Base/stopping condition reached
        |
        v
Calls return in reverse order
```

The most important points to remember are:

- **Parameters** are names declared by the function; **arguments** are values supplied when calling it.
- Required parameters need values.
- Default parameters provide fallback values.
- Keyword arguments use parameter names and therefore need not rely solely on positional order.
- `*args` collects an arbitrary number of positional arguments into a tuple.
- `return` sends a result back to the caller.
- Recursion occurs when a function calls itself.
- Recursive logic must eventually reach a stopping/base condition.
- Statements after a recursive call execute while the call stack unwinds.

These concepts are fundamental for writing reusable Python code and become especially important as programs grow into larger applications, data-processing pipelines, and AI/ML projects.
