## 1. Custom exceptions and `raise`

An **exception** signals that an operation could not complete normally. Python provides built-in exceptions such as `ValueError` and `ZeroDivisionError`; you can also define your own exception class for application-specific rules.

**Lecture example: raise a custom exception for an underage voter.**

```python
class InvalidAgeError(Exception):
    pass


class Check:
    def can_vote(age):
        if age >= 18:
            print("Person can vote")
        else:
            err = InvalidAgeError()
            raise err


age = int(input("Enter age : "))
Check.can_vote(age)
```

- `InvalidAgeError(Exception)` defines a new exception type inheriting from `Exception`.
- `pass` means no extra implementation is required.
- `raise err` stops normal execution and propagates the exception to a handler (if one exists).
- `Check.can_vote(age)` works here because the function has no `self` parameter and is called on the class. In production code, explicitly mark such a function with `@staticmethod`.

**Example output for age 16:** an unhandled traceback ending with `InvalidAgeError`.

## 2. Exception messages and handling

### 2.1 Attach a message using the built-in exception constructor (recommended)

```python
class InvalidAgeError(Exception):
    pass


class Check:
    @staticmethod
    def can_vote(age):
        if age >= 18:
            print("Person can vote")
        else:
            raise InvalidAgeError("Low Age")


try:
    age = int(input("Enter age : "))
    Check.can_vote(age)
except InvalidAgeError as msg:
    print(f"Exception : {msg}")
except ValueError:
    print("Exception : Please enter a valid integer age")
```

**Input:** `16`  
**Output:** `Exception : Low Age`

**Input:** `20`  
**Output:** `Person can vote`

### 2.2 Lecture's custom `__init__` version — and its subtle issue

The screenshot demonstrates an exception constructor storing a message in `self.msg`:

```python
class InvalidAgeError(Exception):
    def __init__(self, msg):
        self.msg = msg
        return
```

This demonstrates instance attributes, but it is **not the preferred implementation**: simply storing `self.msg` does not explicitly initialize the base `Exception` object. Use `super().__init__(msg)` so the message is registered with the exception:

```python
class InvalidAgeError(Exception):
    def __init__(self, msg):
        super().__init__(msg)
        self.msg = msg
```

If no additional fields or behavior are needed, `class InvalidAgeError(Exception): pass` is sufficient; Python already supports `InvalidAgeError("Low Age")`.

### 2.3 `raise` versus `except`

| Statement | Purpose |
|---|---|
| `raise InvalidAgeError("Low Age")` | Creates and raises a custom exception |
| `except InvalidAgeError as msg:` | Catches that particular exception |
| `str(msg)` | Reads the human-readable exception message |
| `except ValueError:` | Handles invalid numeric input separately |

**Important:** The lecture note says to handle the exception while calling the method. More precisely, a matching `except` must surround the code path where the exception propagates; the handler can be in the caller or at a higher level.

## 3. Generic exception handling

The earlier lecture's list-index/division example reappears in the screenshots:

```python
nums = [3, 8, 9, 0, 4, 6, 5, 2, 0]

try:
    x = int(input("Enter first loc : "))
    y = int(input("Enter second loc : "))

    a = nums[x]
    b = nums[y]
    c = a / b
    print(f"Quotient : {c}")

except Exception as msg:
    print(f"Exception : {msg}")
```

Sample outcomes:

| Inputs | Result |
|---|---|
| `1`, `4` | `Quotient : 2.0` (`8 / 4`) |
| `1`, `3` | `Exception : division by zero` |
| `13`, `1` | `Exception : list index out of range` |
| `abc` | `Exception : invalid literal for int() with base 10: 'abc'` |

`Exception` catches many ordinary application exceptions, including `ValueError`, `IndexError`, and `ZeroDivisionError`, but **not every possible exception** (for example, `KeyboardInterrupt` inherits directly from `BaseException`). Prefer specific handlers when you know how to recover.

```python
try:
    x = int(input("Enter first loc : "))
    y = int(input("Enter second loc : "))
    print(nums[x] / nums[y])
except ValueError:
    print("Enter numeric indices")
except IndexError:
    print("Index outside the list")
except ZeroDivisionError:
    print("The selected divisor is zero")
```

Note that Python accepts negative list indices, e.g. `nums[-1]`. Validate `0 <= index < len(nums)` if the user must enter only nonnegative positions.

## 4. DBMS, RDBMS and foreign keys

A **DBMS** manages stored data. An **RDBMS** stores related data in tables and supports relational constraints such as primary keys and foreign keys. MySQL is an RDBMS.

### 4.1 Why normalize the data?

The screenshot begins with a `Students` table containing repeated course names, fees, and durations:

| sid | sname | course | fee | duration |
|---|---|---|---|---|
| 1 | A | Python | 25000 | 4Mon |
| 2 | B | Java | 30000 | 6Mon |
| 3 | C | Java | 30000 | 6Mon |
| 4 | D | Python | 25000 | 4Mon |
| 5 | E | NULL | NULL | NULL |

Repeating course details wastes storage and creates update anomalies. Instead, separate courses from students.

**Course (parent):**

| cid (PK) | cname | cfee | cduration |
|---|---|---|---|
| 101 | Python | 25000 | 4Mon |
| 102 | Java | 30000 | 6Mon |

**Students (child):**

| sid (PK) | sname | cid (FK) |
|---|---|---|
| 1 | A | 101 |
| 2 | B | 102 |
| 3 | C | 102 |
| 4 | D | 101 |
| 5 | E | NULL |

A **primary key** uniquely identifies each row and cannot be NULL. A **foreign key** refers to a candidate/unique key in another table (typically its primary key). A foreign-key column **can repeat** and **may be NULL if the column is nullable**. If non-NULL, the referenced value must exist, assuming foreign-key checks are enabled.

The diagram's intended relationship is `Students.cid` → `Course.cid`. The slide writes `FOREIGN KEY Students(cid) REFERENCES Course(cid)` as a conceptual description; actual MySQL table syntax appears below.

```sql
CREATE DATABASE IF NOT EXISTS python_course;
USE python_course;

CREATE TABLE Course (
    cid INT PRIMARY KEY,
    cname VARCHAR(50) NOT NULL,
    cfee DECIMAL(10, 2) NOT NULL,
    cduration VARCHAR(20) NOT NULL
);

CREATE TABLE Students (
    sid INT PRIMARY KEY,
    sname VARCHAR(50) NOT NULL,
    cid INT NULL,
    CONSTRAINT fk_students_course
        FOREIGN KEY (cid) REFERENCES Course(cid)
);

INSERT INTO Course (cid, cname, cfee, cduration) VALUES
    (101, 'Python', 25000, '4Mon'),
    (102, 'Java', 30000, '6Mon');

INSERT INTO Students (sid, sname, cid) VALUES
    (1, 'A', 101),
    (2, 'B', 102),
    (3, 'C', 102),
    (4, 'D', 101),
    (5, 'E', NULL);

SELECT s.sid, s.sname, c.cname, c.cfee, c.cduration
FROM Students AS s
LEFT JOIN Course AS c ON s.cid = c.cid;
```

`LEFT JOIN` includes students who have not yet selected a course.

## 5. Connecting Python to MySQL

- An account with permissions for the relevant database.


### 5.3 Safer connection pattern

Keep credentials out of source code. Set environment variables such as `MYSQL_USER`, `MYSQL_PASSWORD`, and `MYSQL_DATABASE` in your environment.

```python
import os
import mysql.connector

conn = None
try:
    conn = mysql.connector.connect(
        host=os.getenv("MYSQL_HOST", "localhost"),
        user=os.environ["MYSQL_USER"],
        password=os.environ["MYSQL_PASSWORD"],
        database=os.getenv("MYSQL_DATABASE", "ashokit"),
    )
    print("Connection opened...")
except (mysql.connector.Error, KeyError) as exc:
    print(f"Connection failed: {exc}")
finally:
    if conn is not None and conn.is_connected():
        conn.close()
        print("Connection closed")
```

Use a dedicated least-privilege database user rather than `root` for applications.

## 6. Creating a MySQL table

The screenshot shows `CREATE TABLE account(num int, name varchar(20), balance int)` executed using a cursor.

```python
import mysql.connector

conn = None
cur = None
try:
    conn = mysql.connector.connect(
        host="localhost", user="root",
        password="YOUR_LOCAL_PASSWORD", database="ashokit"
    )
    print("Connection opened...")
    cur = conn.cursor()
    query = "CREATE TABLE IF NOT EXISTS account (num INT PRIMARY KEY, name VARCHAR(20), balance INT)"
    cur.execute(query)
    print("Table is created...")
except mysql.connector.Error as msg:
    print(f"Exception : {msg}")
finally:
    if cur is not None:
        cur.close()
    if conn is not None and conn.is_connected():
        conn.close()
        print("Connection closed")
```

**Expected output:**

```text
Connection opened...
Table is created...
Connection closed
```

`IF NOT EXISTS` lets the example be rerun without a “table already exists” error. The screenshot's original schema does **not** define a primary key; this improved version adds one so duplicate account numbers cannot be inserted. `CREATE TABLE` is DDL, and MySQL normally performs an implicit commit for it.

## 7. Inserting one record

The lecture collects an account number, name, and balance, then executes an `INSERT`. The original screenshot constructs SQL using an f-string:

```python
# Lecture demonstration only — do NOT use with untrusted input:
# query = f"insert into account values({num}, '{name}', {balance})"
# cur.execute(query)
```

This is vulnerable to SQL injection and breaks when names contain quotes. Use **parameterized SQL** instead.

```python
import mysql.connector

conn = None
cur = None
try:
    conn = mysql.connector.connect(
        host="localhost", user="root",
        password="YOUR_LOCAL_PASSWORD", database="ashokit"
    )
    print("Connection opened...")
    cur = conn.cursor()

    num = int(input("Enter acc num : "))
    name = input("Enter name : ")
    balance = int(input("Enter balance : "))

    query = "INSERT INTO account (num, name, balance) VALUES (%s, %s, %s)"
    cur.execute(query, (num, name, balance))
    conn.commit()

    if cur.rowcount == 0:
        print("Insertion failed")
    else:
        print("Record inserted successfully")
except (mysql.connector.Error, ValueError) as msg:
    if conn is not None and conn.is_connected():
        conn.rollback()
    print(f"Exception : {msg}")
finally:
    if cur is not None:
        cur.close()
    if conn is not None and conn.is_connected():
        conn.close()
        print("Connection closed")
```

Example run:

```text
Connection opened...
Enter acc num : 101
Enter name : amar
Enter balance : 5000
Record inserted successfully
Connection closed
```

**Important correction:** The first insert screenshot omits `conn.commit()`. Without committing, a successful `execute()` does not necessarily persist the record when the connection closes; Connector/Python defaults to autocommit off. The later screenshot correctly adds `conn.commit()`.

## 8. Inserting multiple records

The screenshots add `while True`, prompt for another record, and stop when the user types `n`. Here is the corrected, reusable version:

```python
import mysql.connector

conn = None
cur = None
try:
    conn = mysql.connector.connect(
        host="localhost", user="root",
        password="YOUR_LOCAL_PASSWORD", database="ashokit"
    )
    print("Connection opened...")
    cur = conn.cursor()

    while True:
        num = int(input("Enter acc num : "))
        name = input("Enter name : ")
        balance = int(input("Enter balance : "))

        query = "INSERT INTO account (num, name, balance) VALUES (%s, %s, %s)"
        cur.execute(query, (num, name, balance))
        conn.commit()  # Required for persistence of DML when autocommit is off

        if cur.rowcount == 0:
            print("Insertion failed")
        else:
            print("Record inserted successfully")

        choice = input("Do you insert another record(y/n) : ").strip().lower()
        if choice == "n":
            break

except (mysql.connector.Error, ValueError) as msg:
    if conn is not None and conn.is_connected():
        conn.rollback()
    print(f"Exception : {msg}")
finally:
    if cur is not None:
        cur.close()
    if conn is not None and conn.is_connected():
        conn.close()
        print("Connection closed")
```

Example run (matching the lecture's sequence):

```text
Enter name : annie
Enter balance : 6000
Record inserted successfully
Do you insert another record(y/n) : y
Enter acc num : 103
Enter name : harin
Enter balance : 7000
Record inserted successfully
Do you insert another record(y/n) : y
Enter acc num : 104
Enter name : jai
```

The lecture's `if choice == 'n': break` exits only on lowercase `n`; using `.strip().lower()` also accepts `N` and extra whitespace. A stricter application should reprompt for any answer other than `y` or `n`.

### SQL operations and transactions

| Category | Examples | Notes |
|---|---|---|
| DDL | `CREATE`, `ALTER`, `DROP` | Defines schema; MySQL generally implicitly commits DDL |
| DML | `INSERT`, `UPDATE`, `DELETE` | Changes rows; normally requires `commit()` with autocommit disabled |
| Query | `SELECT` | Reads rows; use `fetchone()` or `fetchall()` |
| Transaction | `commit()`, `rollback()` | Saves or undoes uncommitted transactional changes |

`cur.rowcount` reports affected rows for DML; it is **not** a universal test of whether a query succeeded. A failed `execute()` typically raises an exception.

## 9. Common errors and fixes

| Symptom | Typical cause | Resolution |
|---|---|---|
| `ModuleNotFoundError: No module named 'mysql'` | Connector not installed in the active interpreter | Run `python -m pip install mysql-connector-python` using the matching interpreter |
| `1045 (28000): Access denied` | Wrong password, user, host grants or auth configuration | Check credentials and grants |
| `1049 (42000): Unknown database` | Database missing or misspelled | `CREATE DATABASE IF NOT EXISTS ashokit;` |
| `1064 (42000): SQL syntax error` | Malformed SQL or quoting | Use parameterized SQL and check SQL syntax |
| `1050 (42S01): Table already exists` | Re-running plain `CREATE TABLE` | Use `IF NOT EXISTS` when appropriate |
| `1062 (23000): Duplicate entry` | Duplicate primary/unique key | Use a new account number or explicitly implement an update/upsert |
| Insert seems successful but row disappears | Missing `commit()` | Commit the transaction before closing |
| `ValueError` | Invalid integer input | Validate input or catch `ValueError` |

The lecture displays error `1064` before a successful insert; the exact typo is not fully established by the screenshots, so do not assume a specific SQL defect without the complete failing statement.

## 10. Professional consolidated example

The following is a small end-to-end learning script. It avoids hardcoded secrets, uses parameterized queries, creates a table, inserts repeatedly, and reliably closes resources. Set `MYSQL_USER` and `MYSQL_PASSWORD` before running.

```python
import os
import mysql.connector
from mysql.connector import Error


def main():
    conn = None
    cur = None
    try:
        conn = mysql.connector.connect(
            host=os.getenv("MYSQL_HOST", "localhost"),
            user=os.environ["MYSQL_USER"],
            password=os.environ["MYSQL_PASSWORD"],
            database=os.getenv("MYSQL_DATABASE", "ashokit"),
        )
        cur = conn.cursor()
        cur.execute("""
            CREATE TABLE IF NOT EXISTS account (
                num INT PRIMARY KEY,
                name VARCHAR(20) NOT NULL,
                balance INT NOT NULL
            )
        """)

        while True:
            try:
                num = int(input("Account number: "))
                name = input("Name: ").strip()
                balance = int(input("Balance: "))
                if not name or len(name) > 20:
                    raise ValueError("Name must contain 1–20 characters")
                if balance < 0:
                    raise ValueError("Balance cannot be negative")
            except ValueError as exc:
                print(f"Invalid input: {exc}")
                continue

            try:
                cur.execute(
                    "INSERT INTO account (num, name, balance) VALUES (%s, %s, %s)",
                    (num, name, balance),
                )
                conn.commit()
                print("Record inserted successfully")
            except Error as exc:
                conn.rollback()
                print(f"Database error: {exc}")

            choice = input("Insert another record? (y/n): ").strip().lower()
            if choice != "y":
                break

        cur.execute("SELECT num, name, balance FROM account ORDER BY num")
        print("Saved accounts:")
        for row in cur.fetchall():
            print(row)

    except (Error, KeyError) as exc:
        print(f"Setup/connection error: {exc}")
    finally:
        if cur is not None:
            cur.close()
        if conn is not None and conn.is_connected():
            conn.close()
            print("Connection closed")


if __name__ == "__main__":
    main()
```

**Learning note:** A real financial application should use `DECIMAL` for money, enforce account ownership and authorization, maintain an audit trail, and use carefully designed transactional business operations. This course's `balance INT` table is a teaching example, not a banking system.

### Quick revision

- Custom exceptions are classes that usually inherit from `Exception`.
- `raise` signals a problem; `try`/`except` handles it.
- `except Exception as msg` can display many common runtime error messages, but specific handlers are preferable when practical.
- A primary key uniquely identifies a row; a foreign key enforces references between tables.
- `mysql.connector.connect()` opens a database connection; `cursor().execute()` runs SQL.
- Parameter placeholders `%s` protect data values from SQL injection.
- `commit()` persists transactional DML changes; `rollback()` undoes pending changes.
- Always close cursors and connections, including after errors.
